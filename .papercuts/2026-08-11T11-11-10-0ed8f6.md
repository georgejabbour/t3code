Running the whole monorepo suite with 'pnpm test' fails intermittently with 'Hook timed out in 30000ms' in apps/web/src/components/chat/MessagesTimeline.test.tsx, and separately in apps/mobile/src/features/diffs/nativeReviewDiffHighlighter.test.ts. Both pass in well under a second when their own project runs alone. The cause looks like module import time, not test logic: the full run reports 675 seconds of cumulative import across workers, and MessagesTimeline.test.tsx does a dynamic import inside beforeAll. A green per-project run and a red full run makes it hard to tell a real break from load noise. Fix: raise hookTimeout for the files that import a large component graph inside a hook, or lower the worker count for the aggregate run.

The server suite shows the same pattern. One run of `vp run --filter t3 test` reported `1 failed | 2432 passed`, and three later runs of the same command each reported `2433 passed` with exit code 0. The failing test name was not captured, so the flake is still unidentified. Whatever the fix, the suite should name a flaky test loudly enough to survive a summary line, because an unnamed intermittent failure costs a full re-run to even identify.
